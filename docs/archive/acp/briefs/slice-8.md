## Part A: orchestrator edits through the engine's internal tools (decision already taken, implement it)
Real runs (slice 6) showed claude-agent-acp and cursor-agent acp edit files with internal tools: no `fs/write_text_file` reaches the client, so the hub's edit guard cannot see those edits. Decision, three layers, none of which silently overrides the user's engine mode:
1. While the session's `editsAllowed` is false, any `session/request_permission` the engine sends whose toolCall kind is `edit`, `delete` or `move` (or `execute` with a command the guard flags as a repo write, reuse src/guard.mjs editVerdict/bashLooksLikeRepoWrite) is NOT forwarded to Zed: the hub answers the engine itself with the reject option (prefer `reject_once`/`reject_always` kinds present in the options; if none, cancelled), writes one agent_message_chunk 'El orquestador no edita archivos: delega con spawn_agent (o /edits on)' (deduplicated per tool call), and appends an audit line like the hook's. With `/edits on` requests pass through to Zed unchanged.
2. After-the-fact detection for engines that edit without asking (bypassPermissions in claude, agent mode in cursor): observe the child's session/update stream; a `tool_call` or `tool_call_update` with kind `edit|delete|move` whose locations (or content diffs) point inside the session cwd and outside `.zedpstack/`, seen while `editsAllowed` is false, produces ONE warning chunk per tool call ('⚠ El orquestador editó <ruta> directamente (el motor no pidió permiso). Revisa con git diff; usa /edits on si fue intencional.') plus the audit line. Exclude tool calls that belong to workers (cards use `zp-` ids) and the hub's own messages.
3. `/edits` (status) must tell the truth: report `editsAllowed`, the engine's current mode when known (from the `mode` option), and the enforcement level: 'bloquea' when the mode is one that asks for edits (claude `default`, `plan`, cursor `ask`/`plan`), 'solo avisa' otherwise (bypassPermissions, acceptEdits, cursor agent), and mention `dispatch install` for the Claude Code hook. Document the matrix in docs/ARCHITECTURE.md and docs/ACP_DESIGN.md.
Tests with the fake engine: edit-kind permission request denied locally with a chunk while off and forwarded while on; execute with a repo-write command denied, a read-only command forwarded; after-the-fact tool_call kind edit inside cwd warns once (not on repeated updates of the same id, not outside cwd, not under .zedpstack, not for zp- cards); `/edits` status text per mode; audit line written. Real check (if the sandbox allows): with the real cursor engine in `agent` mode ask the orchestrator to create `yo.txt`: expect the after-the-fact warning in the transcript (the file will exist; say so) and with `ask`/`plan` mode expect no write. Paste trimmed transcripts.

## Part B: multi-thread hardening
Zed reuses one hub process for all threads. Prove and fix isolation:
1. Tests with N=4 concurrent sessions on the same repo and two repos, each with its own fake engine: cards only for own agents (already by origin), permissions asks route to the right session, `/claude`/`/codex` switch in one session does not disturb the others, cancel in one leaves the others' turns and workers untouched, an engine crash in one leaves the others running, `session/close` of one leaves the rest, engine cap eviction prefers the least recently used idle engine and never one with an active turn, shutdown with 4 sessions leaves zero processes (engines, MCP children, sockets, timers; the hub process exits by itself).
2. Shared state: the prefs file `acp-prefs.json` must be written atomically (tmp + rename) with a read-merge-write per key so two sessions changing different runtimes concurrently never lose each other's values; add a cross-process test (two hub processes) and an in-process interleaving test. The bridge socket directory handles two hubs (distinct pids) and stale cleanup.
3. Resource leaks: open/close 50 sessions in a loop with the fake engine: no growth in open handles (`process._getActiveHandles()` count stable), no timers left, no zombie children (poll pids).
4. Any other race you find while doing this: fix at the root and note it in the final report (one line each, with evidence).
