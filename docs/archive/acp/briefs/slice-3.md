## Goal
In a Zed thread, the engine (claude/codex/cursor child ACP agent) gets the zedpstack MCP server scoped to that thread, receives the zedpstack orchestrator skill automatically on its first prompt, and every worker it spawns shows up live as an expandable card in the thread, whichever process spawned it.

## Build
1. MCP injection (hub.mjs / engine.mjs): when starting an engine for an outer session, pass `mcpServers` = the servers Zed sent in session/new, minus any entry named `zedpstack`, plus ours: `{ name: 'zedpstack', command: process.execPath, args: [<abs path of scripts/mcp.mjs>], env: [{name:'ZEDPSTACK_ACP_SESSION', value: <outer sessionId>}, {name:'ZEDPSTACK_REPO', value: <session cwd>}] }` (ACP stdio mcp server shape: env is an array of {name,value}). The outer session id stays the same across runtime switches, so origin stays stable. Keep this server-spec construction in one pure function (unit-tested).
2. Skill on first prompt: extract `orchestratorPrompt()` from src/mcp/server.mjs into a shared module (e.g. src/orchestratorPrompt.mjs) used by both MCP and the hub (no hub->mcp import). In `session/prompt` forwarded to the engine, the first prompt of each ENGINE session (reset `primed` on runtime switch/restart) gets the orchestrator prompt prepended as an extra leading text block, followed by the user's blocks. Do not prepend for `/board` or for slash commands the engine owns (a prompt whose first line starts with `/` that is a child command: pass through unchanged and do not mark primed).
3. src/acp/cards.mjs (replaces follow.mjs usage for orchestrated turns; keep follow.mjs as the per-agent tail primitive or fold it in, but leave ONE way): `createWorkerCards({ repo, sessionId, notify, pollMs = 300 })` returns `{ start(), resync(), stopTurnAgents?(not now), dispose() }`. It polls listAgentIds(repo) (fs.watch may be used only as a hint), loads each agent with loadAgent, and for agents whose `spec.origin.sessionId === sessionId` and not yet attached, attaches createWorkerUpdateSink + followAgent (existing code in updates.mjs/follow.mjs: kind 'other', cumulative content, 250 ms throttle) emitting tool_call then tool_call_update through `notify` with the OUTER sessionId. Agents already terminal when first seen must still get a tool_call and a final completed/failed update (so a resync at turn start is idempotent and shows finished workers once). Ignore agents of other sessions and of other frontends. Start the watcher when the session is created, `resync()` at the start of every prompt, `dispose()` on session end/shutdown (no leaked timers: unref them and clear on dispose). Cards must keep updating also after the prompt turn that spawned them ended.
