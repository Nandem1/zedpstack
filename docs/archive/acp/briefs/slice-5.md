## Goal
A verdict or a card is never silently attributed to a model the user did not ask for. When a worker asks for `opus` and the CLI runs `claude-opus-4-8`, or asks for `claude-opus-5-5` and gets something else, it is visible everywhere the model is shown and recorded in the result.

## Build
1. src/modelCheck.mjs (pure, unit-tested; one module owns this knowledge): `normalizeModelId(id)` (lower-case; spaces to dashes; strip bracket parameters like `[effort=high,fast=true]`; strip date suffixes `-YYYYMMDD`; strip display decorations such as ` 256K High`; so `Composer 2.5` == `composer-2.5`, `claude-haiku-4-5-20251001` == `claude-haiku-4-5`), `isAlias(slug)` (opus, sonnet, haiku, fable, default, auto, and the other family-only names the repo already treats as aliases; reuse existing lists from modelRouting.mjs instead of duplicating), `expectedModelFor(binding, { probeCache })` (a concrete slug is its own expected id; an alias gets the probe cache `effective` when known, else null), and `checkModel({ requested, effective, expected }) -> { state: 'ok'|'unverified'|'mismatch', requested, effective, expected, note }`: no effective => unverified('no evidence'); expected known and normalized effective differs => mismatch; alias with no expected and effective present => unverified with note `alias <requested> resolved to <effective>` (visible, not an error); equal after normalization => ok. Family-prefix matching is NOT enough: `claude-opus-4-8` must not satisfy expected `claude-opus-5-5`.
2. Workers: `spawnAgent` fills `spec.expectedModel` via expectedModelFor (look up the probe cache from setupWizard without triggering paid probes; if the cache is missing, null). `loadAgent` derives `modelCheck` (pure, from spec + run.effectiveModel; reads never write). Expose `model_check` in agentStatus, agentResult, waitAgents entries, listAgents and the board JSON (additive fields, existing shapes untouched). Board rows and `formatBoardText/Markdown/Ansi`, `workerTitle` in src/acp/updates.mjs and the MCP text board show `requested -> effective` and a warning mark when mismatch (e.g. `opus -> claude-opus-4-8 ⚠ esperado claude-opus-5-5`), and a neutral note for alias resolutions. A mismatch also adds one line to `agentResult.text` header or a `warnings` array so the orchestrator cannot miss it before attributing a verdict; completed mismatching workers stay `completed` (do not fail them) but the card's final content starts with the warning line.
3. If no engine gives reliable evidence, implement nothing speculative: document in docs/ACP_DESIGN.md that orchestrator model is `unverified` and why, with the captured evidence.
