## Goal
Cancelling a turn, a crashing engine, a closed thread or a killed Zed never leaves orphan engines, MCP children or running workers of that turn behind, and never wedges the thread.

## Build
1. Turn model in hub.mjs: a session's active turn records `{ startedAt, controller, promptPromise }`. `session/cancel` (notification) does, in order and idempotently (a second cancel joins the first): (a) forward `session/cancel` to the child engine; (b) abort the turn controller; (c) stop every worker whose `spec.origin.sessionId === <outer session id>` and `spec.createdAt >= turn.startedAt` and whose derived status is not terminal, using the store's stop path (markStop + the existing stop/signal logic from lifecycle.mjs `stopAgent`; add a small exported helper in lifecycle.mjs if needed, with the existing public shapes untouched); workers from EARLIER turns keep running; (d) wait for the child's prompt response (bounded, say 10 s, then treat as cancelled), (e) wait until the stopped workers are actually stopped (cards finished as failed/stopped via cards.mjs; bounded), then answer the outer `session/prompt` with `stopReason: 'cancelled'`. Cancelling while no turn is active is a no-op. Cancelling pending client requests: any `session/request_permission` the child forwarded to Zed and still unanswered must be resolved to `{outcome:{outcome:'cancelled'}}` toward the child.
2. Engine crash during a turn: if the child exits while a prompt is in flight, the outer prompt resolves with `stopReason: 'refusal'` after an agent_message_chunk explaining the engine died (include exit code and the last stderr lines); the session keeps its `zp.runtime` option, `engine` becomes null, workers keep running and their cards keep updating; the next prompt restarts the engine (primed reset, skill prefix again) and first sends a chunk saying the previous conversation was lost. A second prompt while the engine is restarting must not double-start it.
3. Supervision of processes: hub.shutdown (stdin close, SIGTERM, SIGINT, uncaughtException/unhandledRejection in scripts/acp.mjs) stops all session watchers (cards.dispose) and kills every engine's process group (SIGTERM, SIGKILL after 3 s, timers unref'd), then exits; hard kill of the hub (SIGKILL) must still end the engines: they run in their own process group, so add a parent-death watchdog: pass `ZEDPSTACK_PARENT_PID=<hub pid>` in the engine env and in the injected MCP server env; `scripts/mcp.mjs`/src/mcp/server.mjs exits when that pid is gone (poll every 2 s, unref'd, and also on stdin EOF) and the fake engine honors the same env so you can test it. Third-party engines are expected to exit on stdin EOF; the hub additionally kills the group if the engine is still alive 3 s after its stdin is closed. Workers are NOT killed by hub shutdown (D-03), but log one stderr line listing the non-terminal workers left running for that session.
4. Session lifecycle in a process reused across threads: when Zed closes a thread there may be no message; if ACP `session/close` (unstable) or similar arrives, tear that session down (engine kill, cards.dispose); otherwise sessions live until shutdown. Cap: starting a new engine when more than `ZEDPSTACK_ACP_MAX_ENGINES` (default 8) are alive kills the least recently used idle engine (no active turn) and marks that session `engine:null` (it restarts lazily on its next prompt with the "conversation lost" chunk).
5. Repeat the cancel race tests many times (loop 20 in one test or a script) to prove no flake.
