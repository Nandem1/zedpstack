## Goal
Inside a Zed thread, risky zedpstack actions ask the human through Zed's native permission UI, and the orchestrator cannot edit the repo directly unless the user allows it, regardless of what the child engine's own permission mode says (the user's engine mode may be bypassPermissions).

## Build
1. src/acp/bridge.mjs: a local Unix-domain-socket server owned by the hub (path `<ZEDPSTACK_HOME or ~/.zedpstack>/run/acp-<hubpid>.sock`, directory 0700, socket 0600, unlinked on shutdown and stale sockets of dead pids cleaned at start) speaking newline-delimited JSON: request `{id, sessionId, action, agentId?, title, detail}` -> response `{id, allowed: boolean, reason?}`. Client helper `askHuman({ action, agentId, title, detail, env = process.env, timeoutMs })`: if `env.ZEDPSTACK_ACP_BRIDGE` is unset (any non-ACP host: Claude Code, Codex, Cursor over MCP) it resolves `{allowed: true}` immediately with no I/O (hosts unchanged); otherwise it connects, sends the request with `sessionId = env.ZEDPSTACK_ACP_SESSION`, and rejects/denies on connection failure or timeout (default 10 min). Fail closed when the bridge is configured but unreachable.
2. Hub handling: on a bridge request, find the outer session and issue `session/request_permission` to Zed (outer session id) with a toolCall `{toolCallId: 'zp-perm-<n>', title, kind: 'edit'|'execute'|'other' as appropriate, status: 'pending', content: [{type:'content', content:{type:'text', text: <detail: agent id, commit, files, diffStat>}}]}` and options `allow_once` (kind allow_once), `allow_always` (kind allow_always), `reject_once` (kind reject_once). `allow_always` is remembered per (session, action) for the life of the session. A cancelled/closed turn, session close, engine restart or hub shutdown resolves pending asks as denied (`reason` says why) and answers Zed's pending request as cancelled where applicable. Several concurrent asks are independent.
3. Risky actions that ask (in src/mcp/tools.mjs, via askHuman, before doing anything): `apply_agent_changes` (detail: commit, files, diffStat from agentResult), `spawn_agent` of a writer with `isolation: 'none'` (writes in the user's checkout), `close_agent` with `delete_branch` or `remove_worktree` of a writer whose changes were never applied, and `setup_write`. A denial returns the tool's normal JSON shape with `applied:false`/`error:'rejected by user'` style (keep existing shapes, additive fields only) and performs NO side effect; the orchestrator text explains the rejection. Never route read-only operations through the bridge.
4. Edit guard at the protocol boundary (hub): requests the child engine sends to the client that would modify the repo are checked with the existing src/guard.mjs logic (reuse `decide`/`bashLooksLikeRepoWrite`; do not fork the rules): `fs/write_text_file` whose resolved path is inside the session cwd and outside `.zedpstack/` is refused with a JSON-RPC error whose message explains 'el orquestador no edita archivos: delega con spawn_agent (o /edits on)'; `terminal/create` commands flagged as repo writes are refused likewise; everything else passes through. Per-session switch `editsAllowed` (default false), toggled by new hub commands `/edits on` and `/edits off` (announced in available commands, handled locally like /board, confirmed by an agent_message_chunk). When on, the guard lets writes through. Also forward the switch to `dispatch session allow-edits|block-edits` semantics only if the existing marker is per-repo and safe to share; otherwise keep it hub-local and document it.
5. Honest limits: if the engine performs edits internally without client fs/terminal methods, the protocol guard cannot see them. Verify with the real engines which path claude-agent-acp and `cursor-agent acp` use for an Edit/Write tool (they receive fs capabilities from Zed's initialize: pass `fs:{readTextFile:true, writeTextFile:true}, terminal:true` in the scripted client like Zed does) and record the finding in docs/ACP_DESIGN.md. If an engine bypasses the client, say so plainly and note the remaining defense (the PreToolUse hook for Claude Code hosts, `dispatch install`).
